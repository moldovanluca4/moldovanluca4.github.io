Home Lab

My homelab centers around a Raspberry Pi 5 (4 GB RAM, ARM64) running Debian 13 (Trixie), OpenMediaVault 8, and OMV-Extras for local storage, DNS filtering, and Linux experiments. It boots from an EXT4 USB system drive with zram swap while isolating personal shares and dedicated Docker volumes (docker/, compose/, appdata/) onto an external 2 TB Western Digital HDD, running Pi-hole v6 in Docker via OMV Compose with Quad9 DNSSEC-validated upstreams.

Beyond the NAS, the lab repurposes a legacy Fujitsu laptop (<1 GB RAM) for older Ubuntu kernel/hardware compatibility and GUI troubleshooting, as well as a second laptop (4 GB RAM) running Arch Linux after earlier Void Linux experiments. On the Arch machine, I kept the desktop environment and system footprint deliberately restrained; although I originally set it up for security research before moving that work to my main Fedora machine, I now plan to run homelab services on it while carefully managing its 4 GB RAM constraint. Ongoing work also includes salvaged hardware reuse, OpenWrt firewall rules, VLAN segmentation, DNS resolution-path tracing, and Jetson Nano local AI experiments.

Planned Software Projects

I am currently working on Linux Atlas (“Explore, understand, and inspect your Linux systems”), an open-source application that evolved directly from the multi-device Rust terminal tool I originally planned to build for my homelab. What started as a terminal utility for monitoring and working across homelab machines grew into a broader platform aimed at making Linux more accessible to beginners while providing practical system-inspection capabilities for developers and homelab enthusiasts. The project is designed to discover and categorize installed applications, command-line utilities, system services, hardware details, and configuration metadata across different Linux distributions, presenting them through a user-friendly graphical interface with beginner-friendly educational explanations and technical details.

Architecturally, Linux Atlas unifies my C++ and Rust project goals by combining a C++ and Qt graphical interface with a modular, concurrent, read-only Rust inspection engine that supports both local systems and headless remote machines accessed over SSH. Currently in early design and architecture planning, its planned feature set includes distribution-agnostic modular collectors, a fastfetch-powered loading and landing overview when available, system inventory snapshot comparisons, and structured system report exports.
